# SignedPrice 데이터 수집·축적 로드맵

2026년 9월 9일 · 제품 로드맵 보완 · 아래 완료 기준은 계획이며 달성 수치가 아님

**목표:** 도시마다 실제로 비교할 수 있는 거래 범위를 확보하고, 같은 건물의 가격·조건·보유비용이 어떻게 바뀌었는지 근거와 함께 축적한다. 이 자료를 Explore, 건물 상세, 구매 비용 계산과 콘텐츠가 함께 사용한다.

**기본 방향:** 공개 거래 원자료를 가져오는 기능은 출발점이다. SignedPrice가 쌓아야 할 자산은 여러 출처의 동일 건물을 정확히 연결한 기록, 검토한 비용·상태 정보, 수정 이력, 재현 가능한 비교 결과다. 많이 수집한 도시보다 사용자가 후보를 고를 수 있을 만큼 빠짐없이 설명하는 도시를 먼저 만든다.

## 1. 현재 기반과 가장 먼저 메울 빈칸

아래는 기존 코드와 운영 문서를 확인한 범위다. 수집 코드가 있다는 사실만으로 운영에서 정기 갱신되고 있다고 판단하지 않는다. 실제 실행 기록과 공개 자료를 대조해 기준선을 확정한다.

| 영역 | 이미 있는 기반 | 우선 확인·보완할 점 |
|---|---|---|
| 공통 데이터 | 지역·건물/프로젝트·외부 식별자·원출처·거래 관측·공개 버전을 저장하는 구조 | 도시별로 실제 수집·검증·공개까지 연결되는 범위, 누락, 갱신 지연을 한 표로 확인 |
| 서울 | 매매·임대 수집기, 건물 식별, 공식 건물 정보 보강, 공개 실거래 요약 | 구·월별 수집과 정정 반영, 건물 연결 누락, 관리비 등 보유비용 연결 가능 범위 |
| 싱가포르 | URA 민간주택·HDB 자료, 프로젝트/블록 단위 탐색, 소유권·면적·위치 정보 | 민간/HDB 및 매매/임대 범위와 최신성 분리, 장기 임차 조건과 비용의 확인 시점 |
| 두바이 | DLD 자료 정규화, 지역·프로젝트 증거, 완공/분양 구분 | 자동 갱신의 운영 상태, 프로젝트 연결 범위, 검증 가능한 관리비와 인도 일정 |
| 도쿄 | 국토교통성 XIT001 구·분기 수집·검증·공개, 23구 검색 입력 지원 | **진단 당시 예약 수집은 미나토구 `13103` 고정. 선택 가능한 구와 실제 공개 자료가 있는 구가 일치하지 않음** |

도쿄 자료는 **건물명이 없는 익명 지역 거래**다. 23구로 수집을 넓혀도 곧바로 건물별 실거래 이력이 생기지는 않는다. 건물 정보는 별도 식별 출처가 확보된 뒤 연결하고, 연결되지 않은 거래는 계속 지역 비교 자료로 사용한다.

### 저장과 검수: Neon을 기준으로, Sheets는 필요할 때 보조

기존 Neon/PostgreSQL을 수집 자료와 이력의 기준 저장소로 이어간다. 사이트는 기존 데이터베이스·스냅샷 공개 경로를 통해 검증된 공개 버전을 읽는다. 이 결정이 모든 도시의 자동 수집이나 Sheets 연동이 이미 완성됐다는 뜻은 아니다.

| 도구 | 맡길 역할 | 첫 적용 범위 |
|---|---|---|
| **Neon/PostgreSQL** | 수집 기록, 건물 ID와 출처 연결, 거래·비용 관측, 변경 이력과 공개 버전 관리 | 현재 테이블과 수집·검증·공개 절차를 확장. 실패한 새 수집으로 정상 공개 자료가 사라지지 않게 유지 |
| **Google Sheets · 선택 사항** | 사람이 확인할 지역별 수집 현황, 미연결 건물 검수 목록, 콘텐츠 조사 상태 | 필요가 확인되면 Neon의 요약 정보를 **한 방향으로 내보내기**. 데이터 버전·추출 시각·대상 ID를 함께 표시 |

Sheets의 메모나 수정은 검토 제안으로 취급한다. 공개 가격·건물 연결을 바꿀 때는 기존 검증 절차를 거쳐 Neon에 반영한다. 초기 범위에 양방향 동기화는 넣지 않는다. 검수용 내보내기에는 필요한 요약 필드만 담고 인증 정보·원본 전체·개인 정보는 포함하지 않는다.

## 2. 개발 순서와 완료 기준

고정 날짜 대신 각 단계의 증거로 다음 범위를 연다. 1단계와 함께 3단계의 자료 확보 가능성은 조사하되, 확인되지 않은 비용을 먼저 상품 화면에 넣지 않는다.

| 순서 | 수집·개발 작업 | 사용자에게 생기는 변화 | 완료 기준 |
|---|---|---|---|
| **1A · 즉시** | 도쿄 23구 수집 대상과 공개 현황을 맞추고, 공통 비교가 가능한 공식 발표 분기를 우선 채움. 이후 최근 8개 발표 분기의 누락·수정 재수집으로 확대 | 미나토 외 지역을 고르고 같은 분기의 가격을 비교 | 첫 목표 분기의 **23구 모두 수집·검증·공개 상태 확인**. 공식 자료 없음·수집 실패·아직 미수집을 구분. 각 구의 출처 건수와 공개 건수 일치, 반복 수집 중복 없음, 실패 시 기존 공개 자료 유지 |
| **1B · 운영 기반** | 네 도시의 지역×기간×주택유형×거래종류별 수집 범위와 출처 발표 주기를 기록. 실제 실행·공개 시점 대조 | 화면에서 어느 기간과 유형까지 볼 수 있는지 알 수 있음 | 모든 공개 데이터셋에 대상 범위, 최신 출처 기간, 최근 수집 성공일, 공개 버전, 지연 판단 기준 존재. 누락을 분모에서 빼서 커버리지를 높이지 않음 |
| **2 · 동일 건물 연결** | 도시→지역→프로젝트/단지→건물의 기준 ID와 별칭을 정리. 공식 식별자·주소·좌표 등 연결 근거와 검토 상태 보관 | 같은 집이 이름 때문에 중복되지 않고 거래·사진·건물 정보가 한 상세로 모임 | 연결된 항목 전부에 근거와 상태 기록. 도시·주택유형별 표본 검토에서 오연결을 확인하고 수정. 자동 연결은 실제 검토한 정확도와 미연결 비율을 함께 공개한 내부 기준을 통과한 범위에만 적용 |
| **3 · 실제 보유비용** | 도시별 대표 지역에서 검증 가능한 건물/프로젝트 10곳씩을 첫 검토 대상으로 선정. 관리비·수선비·소유권 기간·인도 일정 중 확보 가능한 항목부터 수집 | 같은 매매가격이어도 매달 부담과 앞으로 필요한 돈을 비교 | 각 항목에 적용 대상·금액/단위·기준 기간·출처·확인일 기록. 대상 10곳의 확보/미확보 항목과 이유를 모두 남김. 공개 비교는 충분한 확인 자료가 있는 후보만 포함하며 미확인을 0원으로 계산하지 않음 |
| **4 · 시간에 따른 변화** | 거래 정정, 비용 변경, 건물 정보 갱신과 공개 버전을 누적 보관. 동일 조건 비교를 반복 생성 | 저장한 후보를 다시 볼 때 무엇이 바뀌었는지 이해 | 이전 공개 결과를 재현하고 변경 원인을 추적 가능. 정정·표본 구성 변화·새 거래를 구분. 도시별 근거 있는 비교 콘텐츠 1편과 Explore/비용 계산 연결까지 검증 |

1A의 첫 비교 분기는 달력상 직전 분기와 같다고 가정하지 않는다. 실제 공식 발표와 구별 응답을 확인해 정하며, 아직 발표되지 않은 구·분기는 가격 0이나 거래 0으로 표시하지 않는다. 23구를 한 번에 호출하는 방식보다 제공처의 호출 조건 안에서 진행 상태를 남기고 중단 지점부터 이어가는 방식으로 확장한다.

## 3. 도시별로 무엇을 더 모을 것인가

| 도시 | 우선 축적할 자료 | 확보 경로와 현재 경계 | 구매자가 답할 질문 |
|---|---|---|---|
| **서울** | 같은 단지·전용면적의 매매/전월세 이력, 준공·세대수 등 공식 건물 정보, 기간별 관리비와 수선 관련 확인 자료 | 기존 국토부·공식 건물 정보 연결을 활용. K-apt 등 추가 비용 항목은 제공 범위·연결 키·재사용 조건을 확인한 뒤 적용 | 같은 예산에서 어느 단지가 맞고, 보증금·월세·관리비까지 얼마가 필요한가? |
| **싱가포르** | 프로젝트/블록별 거래, 면적 기준, freehold/leasehold와 임차 시작·잔여 기간, 검증된 관리비 | 기존 URA·HDB 자료 우선. 관리비와 프로젝트 문서는 정식 제공 자료나 사용 권한을 확보한 자료로 보완 | 신규 분양 프리미엄과 넓이·소유권·유지비 차이를 감수할 이유가 있는가? |
| **두바이** | 프로젝트 식별자, 완공/분양별 거래, 관리비 적용 연도·면적 기준, 발표 인도일과 확인 가능한 진행 상태 | 기존 DLD 자료를 기준으로 결합. 추가 프로젝트·관리비·진행 자료는 공식 조회/제공 방식과 저장·재공개 가능 여부를 먼저 확인 | 표시 임대료에서 실제 비용을 빼면 얼마가 남고, 입주 지연에 어떤 비용이 생기는가? |
| **도쿄** | 23구 분기별 거래와 면적·연식·유형, 별도 확인한 건물 관리비·수선적립금·수선 계획·소유권 조건 | XIT001은 지역 비교용으로 유지. 특정 건물 자료는 별도 공개·허가 자료나 동의받은 검토 문서로 확보하며 익명 거래를 억지로 연결하지 않음 | 저렴한 구축의 장기 비용은 얼마이며, 어느 지역과 연식이 예산에 맞는가? |

추가 출처와 비용 항목은 **수집 후보**이며 API 접근권이나 현재 확보를 의미하지 않는다. 자료가 무료인지, 자동 수집이 가능한지, 보관·상업적 재공개를 허용하는지와 호출량 조건을 확인한다. 유료 계약이나 새 접근 승인이 필요한 자료는 범위·가격·대체 경로가 구체화된 뒤 별도 판단한다.

직접 확보하는 자료도 병행할 수 있다. 현지 전문가의 구조화된 확인 기록, 사용 동의를 받은 비용 명세, 직접 촬영하거나 사용 권한을 확보한 사진을 같은 건물 ID에 연결한다. 출처 없는 설명이나 확인하지 않은 현장 방문 표현을 자체 자료로 만들지 않는다. 공개 자료의 접근성과 재현성을 먼저 갖추고, 반복적으로 필요한 빈칸부터 현지 확인에 투자한다.

## 4. 축적할 기록과 화면에 보여줄 정보

| 축적 단위 | 최소 기록 | 사용 방식 |
|---|---|---|
| 원출처·수집 | 제공처, 데이터셋, 요청 지역/기간, 실제 검색·수집 시각, 출처 발표 기간, 원문 참조/해시, 이용 조건 | 누락·정정 확인 및 숫자의 출처 추적. 수집 시각을 계약일이나 자료 기준일로 바꾸지 않음 |
| 대상 식별 | 자체 ID, 공식 외부 ID, 이름/별칭, 상위 지역·프로젝트, 연결 근거, 확인/모호/미확인 상태 | 확실한 항목만 동일 건물로 결합. 지역 중심 좌표와 건물 좌표를 구분 |
| 거래·비용 사실 | 가격/비용, 통화, 기간, 면적 기준, 월/연 단위, 실제값/가정 구분, 적용 대상, 확인일 | 전용·계약·토지 면적을 구분하고 환산 기준일을 유지. 추정 비용은 사용자가 바꿀 수 있는 가정으로 표시 |
| 변경 이력 | 이전 값, 새 값, 유효 기간, 발견 시점, 변경 근거, 계산·공개 버전 | 비용 상승·정정·신규 거래를 설명. 일본 익명 자료의 행 추가/삭제를 특정 매물의 수정·취소로 단정하지 않음 |
| 비교 결과 | 적용 필터, 표본 수, 제외 기준, 데이터 버전, 계산 방법, 가정 | 같은 예산·면적·보유기간의 후보 비교와 근거 있는 기사 재생성 |

Explore에는 사용자의 판단에 필요한 가격·조건·기간·표본을 먼저 보여준다. 자세한 수집·연결 기록은 출처 설명에 둔다. 확인되지 않은 항목을 채우기 위해 지표를 늘리거나, 성격이 다른 도시의 가격을 하나의 순위로 강제 결합하지 않는다.

| 지역·기간 커버리지 | 계획한 지역×기간 셀 중 공개 검증까지 완료한 셀 비율. 별도로 공식 미발표·수집 실패·대기 수를 표시 |
| 자료 최신성 | 제공처의 최신 확인 발표 기간과 사이트 공개 기간의 차이, 마지막 수집 성공 이후 경과. 출처마다 발표 주기·지연 허용 기준 설정 |
| 건물 연결 품질 | 확인 연결 수/전체 대상 수와 검토 표본의 오연결 수를 함께 측정. 식별 불가능한 도쿄 익명 거래를 건물 연결 성공으로 집계하지 않음 |
| 보유비용 충실도 | 선정 후보 중 유효한 출처·단위·확인일을 갖춘 항목 비율. 단순히 값이 존재하는 비율과 구분 |
| 수정 이력 재현성 | 선택한 과거 공개 버전의 가격·표본·비용 계산을 같은 입력으로 재현할 수 있는지 확인 |
| 실제 이용 | 도시별 기사→Explore 이동, 후보 상세 열기, 비교·계산 완료를 집계해 다음 수집 항목 결정. 방문 수만으로 데이터의 효용을 판단하지 않음 |

사용자 행동은 도시·콘텐츠·기능 수준의 비식별 집계부터 활용한다. 검색한 주소, 자유 입력, 개별 자금 사정과 연락처를 이벤트에 넣지 않는다. 저장 후보 자체는 사용자 기능으로 취급하고 수집 데이터와 자동 혼합하지 않는다. 계정 연동·개별 알림은 사용자의 선택과 별도 운영 설계가 갖춰진 뒤 진행한다.

## 6. 이번 개발과 후속 작업의 연결

- [ ] 도쿄 미나토 고정 범위를 해소하고 실제 공개된 구·분기에 맞는 탐색을 제공한다.
- [ ] 네 도시의 수집·공개 기준선을 확정한다. 데이터별 분모와 최신 출처 기간, 운영 성공 기록을 남긴다.
- [ ] 지역·기간 누락이 줄어드는 것을 확인한 뒤 건물 연결 품질을 우선 개선한다.
- [ ] 도시별 첫 10개 후보의 비용 자료 확보 가능성을 검토하고, 확인된 항목을 상세와 비용 계산에 연결한다.
- [ ] 같은 근거로 도시별 비교 기사 1편을 발행하고 실제 탐색·비교 사용을 확인한다.

**첫 실행의 중심:** 도쿄 23구와 네 도시의 갱신 범위다. 이후에는 거래 건수만 늘리기보다 **같은 집을 정확히 식별하고, 실제 비용과 변화를 계속 확인할 수 있게 만드는 작업**에 개발과 취재 시간을 배분한다.
