# SignedPrice 사용자 입력 자료 수집 로드맵

2026년 9월 9일 · 선택적 계산 결과 제공 구현 추가 · 비용·경험 제보와 외부 공개는 후속 단계

**목표:** 공식 거래가 알려주는 가격에, 사용자가 찾는 조건과 실제로 부담한 비용을 더한다. 클릭 횟수와 함께 **어떤 집을 원하는지, 집을 보유하면서 무엇에 얼마를 썼는지**를 사용자의 선택에 따라 구조화해 축적한다.

기존 [데이터 수집 로드맵](./2026-09-09-data-roadmap.md)의 공식 자료·건물 연결·변경 이력에 사용자 기여 자료를 추가한다. 용도가 다른 세 자료를 함께 활용하되 출처와 확인 수준을 구분한다.

## 1. 어떤 입력을 모으고 어디에 쓸 것인가

| 축적할 자료 | 첫 수집 항목 | 입력 위치와 활용 |
|---|---|---|
| **구매 수요·선호** | 관심 도시, 통화별 예산 구간, 면적 구간, 주택 유형, 실거주/임대 목적, 구매 예정 시기·보유기간 구간 | Explore·Passport·비용 계산 완료 후 선택적으로 제공. 사람들이 실제로 찾는 예산과 조건에 맞춰 지역 비교·콘텐츠·수집 우선순위를 정함 |
| **실제 주거·보유비용** | 관리비, 수선적립금, 일회성 특별부담금, 임대 운영비, 적용 월/연도, 통화·면적 기준, 포함 항목 | 건물 상세의 ‘내 비용 공유’에서 구조화된 항목으로 제출. 도시별 비용 가정과 후보 비교의 빈칸을 보완 |
| **구매·입주 경험** | 구매 단계, 실제 소요기간 구간, 서류·송금·대출·인도 지연 등 경험 유형, 발생 시기 | 짧은 선택형 경험 제출부터 시작. 구매 여정의 병목과 확인할 질문을 정리하고 후속 조사에 활용 |

예산은 원 단위의 정확한 입력값 대신 제출 전 정해진 구간으로 바꾼다. 검색 주소, 동·호수, 세밀한 위치, 연락처와 자유 서술을 일반 분석 이벤트로 보내지 않는다. 특정 건물의 비용 제보에 필요한 대상은 별도 제출 화면에서 사용자가 선택한 기준 ID로 연결한다. 그 제보를 해당 사용자의 검색·저장 이력과 자동 결합하지 않는다.

**사용자가 입력한 거래가격이나 비용은 `사용자 제보`다.** 증빙 확인 후에도 공식 실거래로 바꾸지 않으며, 검토한 문서가 뒷받침하는 항목과 기간까지만 `증빙 확인`으로 표시한다. 한 번의 관리비 제보를 건물 전체 평균이나 앞으로의 확정 비용으로 쓰지 않는다.

## 2. 개발 우선순위와 완료 기준

| 순서 | 구현 범위 | 완료 기준 |
|---|---|---|
| **P0 · 선택적 조건 제공** | 도시·예산/면적 구간·유형·목적·시기의 실제 값을 제출하는 별도 경로. 첫 화면은 짧은 안내와 선택으로 구성 | 모든 새 입력 제출 경로가 동일한 명시적 동의 상태를 확인. 제출 전 항목·목적·보유기간을 알 수 있고 동의하지 않아도 검색·계산 사용 가능. 정확한 금액·주소·자유 입력이 수집 기록·분석 로그에 섞이지 않음. 철회·삭제를 실제로 수행 가능 |
| **P1 · 구조화된 비용 제보** | 관리비·수선·특별부담금부터 시작. 기간·통화·금액 기준·포함 항목·대상 연결을 필수로 검토 | 제출 중복, 음수·단위 오류와 비정상 값을 검토 대기 상태로 처리. 일반 제보와 증빙 확인을 구분하고 검토 전 공개하지 않음. 연락처 제출을 필수 조건으로 만들지 않음 |
| **P2 · 증빙과 경험 검토** | 필요한 경우에만 비용 증빙 첨부, 구조화된 구매·입주 경험 추가 | 첨부에서 이름·주소 세부·계좌 등 불필요한 정보를 가리고 접근을 제한. 검토자·확인 범위·수정 버전·보유기한을 기록. 다른 사람의 정보를 포함한 문서를 그대로 공개하지 않음 |
| **P3 · 안전한 집계와 제품 반영** | 도시별 수요 분포와 검토된 비용 범위를 정기 집계해 비교·기사에 활용 | 초기 공개 기준은 **독립 제출자 10명 이상**인 묶음으로 제안. 독립성 확인이 어렵거나 한 사람이 반복 기여한 경우 공개 보류. 작은 표본과 식별 가능한 조합은 숨기며 표본 수·기간·출처 구성을 표시 |

10명은 초기 공개를 위한 최소 운영 기준이며 안전이나 대표성을 보장하는 숫자가 아니다. 공개 수요는 도시·넓은 예산 구간처럼 제한된 조합을 사용하고, 임의의 세부 필터 조합이나 전후 집계의 차이로 개인 입력을 추정할 수 없게 검토한다. 특정 건물 비용 한 건을 공개하려면 일반 통계와 별도의 항목별 공개 동의·문서 검토가 필요하다.

## 3. Neon 저장·검토·삭제 원칙

**Neon에 별도 사용자 기여 영역을 둔다.** 기존 거래 `observations`에는 관리비·수선비 유형이 없으므로 제출·동의·검토 이력과 승인된 비용을 위한 구조를 별도로 설계한다. 공식 거래 관측을 덮어쓰지 않는다. 수집 목적별 동의는 검색 기능, 개인 저장 기능, 연구용 제공, 공개 활용을 구분한다. 이미 브라우저에 저장된 후보나 계산 입력을 새 목적의 자료로 소급 수집하지 않는다.

| 기록 | 필수 내용 |
|---|---|
| 제출 자료 | 제출 ID, 출처 `user_report`, 항목·단위·적용 기간, 허용된 도시/대상 ID, 생성 시각, 중복 검토 상태 |
| 사용 근거 | 제출자가 확인한 안내·동의 버전, 허용 목적, 공개 범위, 동의 시각, 보유기한, 철회·삭제 요청 상태 |
| 검토 이력 | 제보/증빙 확인/반려 상태, 확인한 항목과 근거, 검토 시각, 수정 버전. 철회된 자료는 새 집계·기사 근거에서 제외 |
| 공개 집계 | 포함 기준, 표본 수, 집계 기간·버전, 작은 표본의 비공개 처리, 철회·정정 시 다시 계산할 연결 정보 |

수집 전에 자료별 보유기간과 삭제 경로를 확정한다. 제출자가 계정 또는 제출 시 받은 관리 수단으로 수정·철회·삭제를 요청할 수 있게 하고, 제출 원문·첨부·불필요한 연결 식별자를 함께 처리한다. 감사 기록에는 삭제 사실과 처리 시점 등 필요한 최소 정보만 남긴다. 개인별 자료를 지워야 하는 상황에서 수정 이력 보존을 이유로 원문을 계속 보관하지 않는다.

Google Sheets가 필요하면 작은 표본을 제외한 **집계 요약만 단방향 내보내기**로 시작한다. 사용자 제출 원문·증빙·연락처는 내보내지 않는다. 기존 Google/Vercel 분석에는 허용된 기능·도시 수준 이벤트만 유지하고, 새로운 사용자 기여 자료는 목적이 명시된 자체 제출 경로에서 다룬다.

## 4. 최초 조사와 구현 진척

구현 전 조사에서 도구 이벤트는 `market/surface/tool` 등을 남기고 입력 금액·주소·검색어를 제외한다. Google 사용자 정의 이벤트와 Vercel 분석 URL에는 쿼리 제거가 적용되지만, GA 초기 설정에는 같은 처리가 확인되지 않아 모든 경로의 정제가 완료됐다고 보지 않는다. 서울·해외 후보는 브라우저 `localStorage`에 저장되고 조건·후보 ID를 조회 API에 보내지만, 해당 경로에는 사용자 입력의 DB 저장이 없다. **현재 GA는 거부 전 기본 허용이고 Vercel Analytics는 별도 환경 설정을 사용하므로, 새 입력 수집에 필요한 명시적 동의가 이미 갖춰진 상태가 아니다.**

기존 Community에는 구조화된 의견·응답 교체/삭제와 5건 기준 공개 코드가 있으나, 현재 API의 DB 연결이 빠져 수집 활성화로 볼 수 없다. 브라우저 쿠키 만료와 DB 자료 자동 삭제도 구분해야 한다. 새 수요·비용 자료의 동의·보유기간·검수와 위의 10명 공개 기준은 별도 구현 대상으로 삼는다.

첫 완료 범위는 **구간화한 조건의 선택적 제공 → Neon 저장 → 철회·삭제 → 검토된 내부 집계**다. 비용·경험과 외부 공개는 다음 단계로 확장한다. 초기에는 사이트를 사용한 사람의 수요와 제출자의 경험으로 설명하고, 특정 도시 전체의 구매자 수요나 평균 보유비용으로 일반화하지 않는다.

확인한 경로: `v2/apps/web/lib/analytics/{tool-events,google-events,url-redaction}.ts`, `v2/apps/web/lib/seoul-shortlist/storage.ts`, `v2/apps/web/lib/global-shortlist/storage.ts`.

9월 9일 후속 구현은 7개 도구의 완료된 결과에 구간 미리보기·명시적 동의·선택적 제출을 추가한다. 자체 `/api/tools/research/`와 Neon `tool_research_submissions`에 허용된 구간·범주, 출처 `user_scenario`, 목적 `product_research`, 동의 버전·시각을 기록한다. 정확한 입력이나 기존 저장 상태는 소급 수집하지 않는다. 브라우저의 불투명한 관리 쿠키로 삭제하며, 쿠키를 삭제하면 기존 자료에 대한 직접 관리 연결은 사라지고 90일 자동 삭제가 적용된다. 내부 집계는 만료된 자료를 제외한 도시·도구별 건수까지만 제공한다.

계산 결과의 제출 경로와 기존 광고·분석 설정은 별개이며, GA 최초 페이지 설정에도 기존 URL 쿼리 제거 규칙을 적용한다. 저장·삭제와 실제 운영 반영은 [구현 계획](./2026-09-09-tools-media-polish.md)의 통합 검증에서 확인한다. 위 P1~P3의 비용 증빙·경험·외부 통계 공개는 이번 구현에 포함하지 않는다.
