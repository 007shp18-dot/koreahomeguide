# SignedPrice 개편 실행 기준

2026-09-08 · 이 문서를 개편의 최신 작업 기준으로 사용한다. 앞선 결정안·로드맵과 다른 내용은 이 문서가 우선한다.

## 1. 확정 방향

영어 사용자가 서울·싱가포르·두바이·도쿄에서 주택을 탐색하고, 실거래와 비용을 비교하고, 향후 고객 매입 지원·중개까지 진행할 수 있는 서비스를 만든다.

- 기본 언어는 영어. 기존 한국어·중국어 콘텐츠와 실제 번역 경로를 보존한다.
- 네 도시는 동일한 선택 구조를 사용한다. 새로운 API가 생겼다는 이유로 일본을 대표 시장으로 우선 배치하지 않는다.
- 승인된 Main·Explore·Ranking 시안의 폰트, 여백, 색상, 간결한 구성을 사용한다.
- Explore는 **작은 썸네일을 붙일 수 있는 촘촘한 목록**이다. 큰 사진 카드 그리드는 채택하지 않는다.
- 큰 사진·갤러리는 **독립 건물 상세**에 집중한다. 건물과 실제 판매 중인 호실을 구분한다.
- 가격 랭킹은 **높은 가격부터** 표시한다. 대표 가격, 단일 최고 거래, 면적당 가격을 분리한다.
- 기존 Tools의 기능을 유지하고 정식 메뉴에 포함한다. Check an offer는 가격 검토로 가는 단축 동선이다.
- 기존 운영 Next.js/Vercel/Neon 구조를 유지한다. Sites 시안은 디자인 참고 자료이며 그 실행 환경과 고정 예제 데이터를 운영으로 통째로 옮기지 않는다.
- 두바이는 사용자가 확인한 유료 활용 가능 조건을 반영해 유료 리포트·매입 지원·중개 범위에 포함한다.

시안:
- Main: https://signedprice-design-study.snappy-rose-0713.chatgpt.site/concept
- Explore: https://signedprice-design-study.snappy-rose-0713.chatgpt.site/concept/explore
- Rankings: https://signedprice-design-study.snappy-rose-0713.chatgpt.site/concept/rankings

시안은 화면 구성의 기준이다. 현재 시안의 18개 선택 사례, 건물 사진 대신 중립 아이콘, 브라우저별 저장, 상세 팝업은 운영 최종 기능을 뜻하지 않는다. Tools 메뉴와 독립 건물 상세는 운영 이식 작업에 반드시 포함한다.

## 2. 다시 확인한 현재 상태

운영 도메인 www.signedprice.com의 Vercel 배포는 READY, production이며 소스는 `6f85c351121967eec4c2d301ecc41b2ff43d62d6`이다. GitHub main과 일치했다. 최신 배포 목록에 나타나는 일본 미리보기는 별도 Preview이므로 운영 배포와 구분했다.

| 항목 | 이번 재확인 | 작업에 미치는 영향 |
|---|---|---|
| 운영 Home | Passport 예산 입력 → 서울·싱가포르·두바이 → 최근 분석 | Passport 유지, 첫 화면을 승인된 사진·검색 구성으로 변경 |
| 서울 Explore | 매매·전세·월세, 지역·건물 검색, Split/List/Table/Map, 건물별 근거 경로 | 시안의 간단한 목록으로 기능을 축소하지 않고 기존 검색·지도·복귀 동작을 보존 |
| 서울 Rankings | 가격 분산이 첫 지표, 대표 매매가격은 낮은 순. 일부 지표는 Preparing | 높은 가격 기본값으로 변경, 미지원 지표는 기본 화면에서 제외 |
| Tools | 운영 허브에서 7개 도구와 도시별 예산 탐색 연결 확인 | 계산 기능·입력 조건·추적 식별자를 보존하고 목적별로 재분류 |
| News / Guides | 자체 기사·외부 기사 목록, 정책 트래커, 11개 가이드 확인 | 유효한 콘텐츠와 URL 유지, 영어 편집과 내부 연결 강화 |
| Properties / Invest / Community | 기존 경로·구성 존재. 웹 수집본 일부는 2–4일 전 | 준비중 화면과 메뉴는 정리하되 경로·유효한 정보·수정 기능은 개별 검토 |
| 서울 수집 키 | 운영 코드가 기본 키와 DATA_GO_KR_SERVICE_KEY 별칭을 모두 처리 | 과거 키 명칭 수정 작업을 반복하지 않음. 실제 실행·저장 결과를 확인 |
| 국가별 수집 | 한국·싱가포르·두바이의 수집·저장 코드와 일정이 이미 존재 | 새 수집기를 중복 제작하지 않고 허용 설정·실행·공개 흐름을 검증 |
| 일본 PR #242 | open / draft / unmerged | 검증된 서버 API 연결을 반영하고 저장·정기 수집을 추가 |

이번에는 운영 페이지·소스·배포 상태를 재확인했다. 아래 데이터 건수와 마지막 수집 실행 결과는 같은 날 앞선 읽기 전용 점검 기록이며, DB를 다시 전수 조회한 값은 아니다. 웹 도구의 캐시 미스는 실제 페이지 장애로 판정하지 않았다.

상단: **Explore / Rankings / Tools / News & Insights / Guides**

오른쪽: **Saved / EN / Check an offer**. 로고는 Home. 현재 도시를 유지한 상태로 다음 기능으로 이동한다. 보조 언어가 없는 화면은 실제 지원 언어로 안내하며 존재하지 않는 번역 URL을 만들지 않는다.

삭제는 대부분 메뉴·중복 화면·불필요한 표현에 관한 결정이다. 데이터·계산기·기사·수집 코드를 일괄 삭제하지 않는다. 준비중 URL은 목적이 같은 대체 화면이 있을 때 이전하고, 다른 서비스를 같은 것처럼 연결하지 않는다.

건물 상세 → Check → 비용 시나리오 이동 시 도시, 건물 식별자, 면적, 주택 유형, 통화, 입력 가격, 돌아갈 근거 URL을 전달한다. 도시를 변경하면 다른 국가의 가격·임대료 입력이 남지 않게 기존 초기화 동작을 유지한다. 숫자를 입력하기 전부터 예시 수익률을 실제 예상 수익처럼 표시하지 않는다.

## 5. Explore·사진·건물 상세

Explore 한 행: **작은 대표 썸네일 / 건물명·위치 / 면적·기간·표본 / 가격 / Save**.

- 사진이 없으면 작은 중립 아이콘 또는 사진 없는 행을 제공한다. 사진 부족 때문에 검색 결과를 숨기지 않는다.
- 목록의 전체 크기 사진을 축소 표시하지 않는다. 허용된 원본에서 썸네일을 만들고, 표시 전용 공급자는 허용 방식 그대로 사용한다.
- 초기 구현 목표: 목록 20개씩 조회, 썸네일 96–160px 표시 및 고해상도 화면용 작은 파생본, 사진이 있는 행만 요청. 목표 파일 크기는 썸네일당 40KB 이하로 잡고 실제 화질과 권리 조건에 맞춰 조정한다.
- 화면 근처 사진부터 불러오며 이미지 영역 크기를 미리 확보한다. 지도는 사용자가 Map/Split을 열 때 로드한다.
- 상세 갤러리는 상세 진입 시 대표 사진부터 불러오고 나머지는 뒤에서 로드한다. 검증된 사진 한 장이면 한 장만 표시한다.
- 카드·건물명 클릭은 독립 건물 URL로 연결한다. 뒤로 가면 검색·정렬·페이지·지도 범위와 목록 위치를 복원한다.
- 건물 외관·공용시설·주변·호실 실내·모델하우스·렌더·평면도의 종류를 구분한다.
- 일본 익명 거래를 지역·면적 유사성만으로 특정 건물 사진과 연결하지 않는다.

기존 사진 점검에서 승인 사진은 외관 80장·항공 1장이었고 실내는 확인되지 않았다. 대규모 갤러리를 전제로 하지 않는다. 이번 시안 작업에서는 개별 건물 사진 조회가 완료되지 않아 중립 아이콘을 사용했다. 첫 작업에서 승인 사진과 실제 건물 ID의 연결부터 확인한다.

## 6. Rankings와 콘텐츠

### Rankings

기본은 선택 도시·기간·거래 종류·주택 유형·면적 범위의 **Median sale price, high to low**다. Highest recorded sale은 검증된 단일 거래 순위, Price per sqm은 같은 관측의 가격·면적이 함께 검증된 자료로 별도 제공한다.

- 전체 조회 결과를 서버에서 정렬한 뒤 페이지를 나눈다. 첫 20개를 화면에서만 재정렬해 전체 순위처럼 보이지 않게 한다.
- 동일 가격의 순서는 안정적인 식별자로 결정해 페이지 사이 중복·누락을 방지한다.
- 표본 수, 기간, 집계 단위와 통화가 같아야 비교할 수 있다. 최소 공개 표본 등 현재 데이터의 공개 규칙을 유지한다.
- 건물·지역 중간값에 단일 최고 거래가격을 섞지 않는다. 지역 집계만 있으면 건물 순위를 만들어내지 않는다.
- 가격 없는 항목과 미지원 지표는 0원·0%로 바꾸지 않는다. 사진·제휴비가 가격 순위에 영향을 주지 않는다.
- 한국 임대의 보증금과 월세는 함께 설명하며 임의 환산으로 혼합 순위를 만들지 않는다.
- 시안의 6개 선택 사례 순위를 운영 도시 전체 순위로 복사하지 않는다.

### News & Insights / Guides

- Insights: 가격·건물·예산·시장 분석. 결론, 핵심 도표, 관련 건물, 해당 조건으로 Explore.
- News: 선별된 변화, 영어 요약, 날짜, 출처, 관련 지역/가이드. 원문 언어는 보조로 제공.
- Policy: 적용 대상, 시행일, 확인일, 공식 근거, 변경 이력.
- Guides: 매입·임대의 상시 절차·비용·체크리스트. 뉴스와 분리하고 마지막 검토일을 표시.
- 기존 기사 주소·편집·발행 기능은 보존한다. 자동 수집 원문 목록과 편집된 기사의 상태를 분리한다.
- 동일 기사·일반 정치 발언·지역 무관 기사는 공개 피드에서 제외한다. 원문 전체 복제 대신 요약과 출처 링크를 제공한다.
- Insights·News·Policy의 각 글은 관련 도시·건물·도구로 연결한다. 글을 읽고 조건을 다시 입력하지 않게 한다.
- 1,226건의 과거 수집 자료는 당시 검토 대기 상태였으며 발행 완료 기사 수가 아니다.

## 7. 시장별 데이터 운영 기준

아래 건수는 앞선 2026-09-08 실측이다. 운영 페이지의 공개 스냅샷 건수와 다를 수 있으며 중복 합산하지 않는다.

| 시장 | 확보 기반 | 운영 개편 범위 | 우선 데이터 작업 |
|---|---|---|---|
| 서울 | Neon 매매 50,177·임대 177,641. 매매 조회용 자료는 건물별 최근 최대 20건 | 매매·전세·월세, 지역·건물 가격, 지도, 비교·수수료 도구 | 기존 수집기의 실행·공개 결과 검증, 전체/보유 표본 구분, 취소·정정 반영 |
| 싱가포르 | 민간 매매 133,942·3,862 프로젝트. HDB는 별도 운영 스냅샷 | Private/HDB 구분, 프로젝트·블록별 가격, 주변 정보 | 매매·임대 식별자 연결, 실제 임대 저장·공개 범위 확인, 갱신 활성화 검증 |
| 두바이 | 46개 지역·56개 선택 프로젝트 집계. 프로젝트는 Off-plan 55·Ready 1 | 지역·선택 프로젝트, Ready/Off-plan·임대 비교 | 이미 있는 수집기의 공급 경로와 실행 설정 확인, 기존 파일을 버리지 않고 버전 있는 공개 자료로 편입 |
| 도쿄 | 공식 API 호출 197건, 미나토 2025 Q4. 공동주택 시안 169건 | 익명 거래·지역·면적·평면·준공·분기 필터 | PR242 운영 반영 준비, 원본·지역 기반 거래 저장, 분기 재수집·정정, JPY |

일본의 건물명·호실·정확한 주소는 이 API로 확보했다고 표시할 수 없다. 현재 글로벌 observations 모델의 필수 건물 식별자에 맞추려고 가짜 건물을 만들지 않는다. 일본은 지역을 주체로 하는 거래 저장 모델을 별도로 추가하고, 공개 조회에서는 건물 거래와 지역 거래를 명시적으로 구분한다.

### 공통 데이터 흐름

**공급 API/파일 → 원본 수집 이력 → 정규화·식별자 연결 → 품질 검사 → 공개 버전 → Explore / Rankings / Tools / 콘텐츠**

기존 국가별 수집기와 `source_records`, `observations`, `property_entities`, `geographies`, `evidence_releases` 등을 재사용한다. 새로 데이터베이스를 갈아엎거나 모든 수집 코드를 다시 쓰지 않는다.

1. 원본: 허용된 응답을 보관하고 출처, 요청 지역·기간, 수신 시각, 파서 버전, 해시, 실행 ID를 기록한다. 대용량 원본은 파일 저장소에 두고 Neon의 object reference로 연결한다. 기존 refresh가 보관하는 제한된 raw_metadata만으로 원본 보존이 끝났다고 보지 않는다.
2. 정규화: 현지 통화·면적 정의·거래 종류·날짜 정밀도·취소·정정 상태를 보존한다. 한국/싱가포르의 월 단위 값을 임의 계약일로, 일본 분기를 임의 날짜로 바꾸지 않는다.
3. 식별자: 건물·프로젝트·동네 ID를 안정적으로 관리하고 별칭·외부 ID를 연결한다. 싱가포르 매매·임대는 현재 다른 ID 네임스페이스를 만들므로 명시적인 매칭을 거친다.
4. 검사: 필수 값·중복·통화·면적·기간·수집 페이지 누락·비정상 급변·매칭 실패를 확인한다. 특이한 거래를 자동으로 ‘저평가’라고 해석하지 않는다.
5. 공개: 수집 배치 전체가 성공하고 검사에 통과한 버전만 공개한다. 기존 코드는 2,000건 단위로 저장하므로 뒤쪽 배치 실패 때 앞쪽 변경이 이미 저장될 수 있다. 새 공개 버전의 승격을 분리해 부분 수집이 사용자 가격을 바꾸지 않게 한다.
6. 조회: 화면별로 따로 계산한 숫자 대신 같은 공개 버전·조건의 조회 모델을 사용한다. 캐시 키에는 시장·공개 버전·필터를 포함한다. 실패 시 마지막 정상 버전과 기준일을 유지한다.

### 사진·뉴스·고객 데이터

사진 파일은 이미지 저장·전송 계층에, 건물 연결·출처·사용 조건·승인자·검토일·종류·대표 이미지 지정은 Neon에 관리한다. `building_photos`와 `media_assets`/공개 media의 연결을 확인해 서로 다른 ‘승인 수’가 화면마다 나오지 않게 한다. 검토 대기·거절 사진은 공개하지 않는다.

뉴스는 수집 원본 → 중복/주제 분류 → 검토 → 발행 → 정정/보관으로 관리한다. 고객의 저장·문의·후보와 공급 원본 자료를 분리하고, 고객이 요청한 매입 지원 범위의 정보만 담당자에게 전달한다.

### 현재 선언된 일정과 운영 점검

다음은 운영 코드의 선언 일정(한국 시간)이며 성공한 실행 이력은 아니다.

| 작업 | 선언 일정 |
|---|---|
| 한국 매매 / 임대 | 매일 03:10 / 03:25 |
| 싱가포르 민간 매매 | 화·금 11:10 |
| 싱가포르 민간 임대 | 매월 16일 11:25 |
| 두바이 거래 / 임대 | 매일 10:10 / 10:25 |
| 뉴스 수집 / 공개 엔터티 투영 | 매일 09:17 / 09:57 |

호출 일정은 이미 있다. 실행 허용 목록·키·공급 경로·실제 수신/저장/공개 결과를 확인한 뒤 필요한 작업을 하나씩 활성화한다. 일본은 최초 분기 수집과 이후 최신 분기 재조회·정정 확인 작업을 추가한다.

내부 상태판에는 시장·자료 종류별 마지막 시도, 마지막 성공, 수신·신규·변경·동일·미매칭 건수, 실패 이유, 다음 실행, 공개 버전·기준일을 표시한다. 기존 10분 lease와 실행 기록은 재사용한다. ‘등록된 API 키 수’나 ‘크론 존재’를 데이터 운영 성공 지표로 쓰지 않는다.

## 8. 개발 묶음과 완료 기준

1차 개편은 0–5 묶음이다. 화면 작업과 데이터 작업은 병행하되 검증된 데이터와 기존 도구가 연결된 상태로 공개한다.

| 묶음 | 결과물 | 완료 기준 | 의존성 |
|---|---|---|---|
| 0. 운영 기준 고정 | 현재 경로·기능·수치 출처 목록, 분리된 개발/미리보기 환경 | 운영 배포 기준과 복구 지점을 알고, 미리보기 테스트가 운영 DB를 수정하지 않음 | 시작 작업 |
| 1. 공통 화면·Home·Tools | 승인 시안의 스타일, 5개 주 메뉴, 네 도시 홈, 7개 기존 도구의 재분류 | 기존 도구·기사·언어 링크가 살아 있고 도시/후보 맥락이 전달됨 | 0. 일본 링크는 해당 route 준비와 함께 공개 |
| 2. Explore·건물 상세 | 작은 썸네일 목록, 지도/표 보기, 독립 상세·사진·거래·위치 | 검색→상세→복귀→저장→Check가 동일 조건으로 작동 | 0·공통 스타일, 검증된 대표 사진 |
| 3. 데이터 공개·일본 | 기존 수집 검증, 원본/정정/공개 버전, 일본 지역 거래 저장·조회 | 한 번의 성공 수집부터 공개 값까지 추적 가능, 실패 배치가 정상 공개 값을 바꾸지 않음 | 0. 화면 작업과 병행 |
| 4. Rankings·콘텐츠 | 높은 가격 서버 정렬, 국가별 유효한 단위, Insights/News/Policy, Guides 연결 | 전체 공개 범위에서 순위 일관성, 기사→Explore/Tools 이동, 유효한 기존 URL 보존 | 1·2·3의 해당 공개 데이터 |
| 5. 운영 전환 | 모바일·속도·접근성·계산·검색 유입·데이터 갱신 검증, 단계 적용 | 아래 출시 체크 통과, 이전 화면/공개 버전으로 되돌릴 수 있음 | 1–4 |
| 6. 첫 유료 서비스 | 건별 검토 리포트·후보 정리·매입 준비 | 실제 이용자의 구매·상담 전환·제공 비용을 측정 | 1차 개편 이후 |
| 7. 매입 지원·중개 | 검증된 실제 매물, 현지 확인·방문·협상·계약 지원 | 담당 파트너·서비스 범위·비용·책임·응대가 정해지고 사례별 진행 추적 | 현지 운영 준비 |

구독·신규 도시·대규모 커뮤니티·공동투자 기능은 첫 개편 범위에 넣지 않는다. 반복 알림 수요, 저장·비교·유료 검토·유효 상담·성사·건별 이익을 보고 확장한다. 사업 중심은 고객 매입 지원·중개다.

날짜를 약속한 일정표는 아니다. 외부 사진·공급·파트너 일정과 실제 작업량을 확인하면서 위 묶음별 완료 기준으로 진행한다. 첫 개발 시작점은 0번과 1번이며 데이터 점검을 병행한다.

## 9. 출시 전 확인

- 기존 계산기에 같은 입력을 넣었을 때 결과와 단위가 보존됨. 세금/수수료 규칙 변경은 디자인 변경과 분리해 확인.
- 네 도시에서 지원하는 단위의 검색·상세·저장·비교가 작동. 도쿄가 서울로 조용히 전환되지 않음.
- 건물·지역·익명 거래, 실제 거래·집계·현재 매물을 구분.
- 높은 가격순 정렬이 페이지 전체에서 일관되고, 결측 값·최소 표본·취소·정정 규칙이 유지됨.
- 사진이 없어도 목록이 유용하고, 사진·지도가 초기 목록을 막지 않음.
- 기존 URL·기사·검색 필터·뒤로 가기·언어 전환이 보존됨. 검색/필터 URL의 기존 noindex 정책도 유지.
- 공급자 장애·부분 수집 실패 시 마지막 정상 공개 데이터가 유지됨.
- 휴대전화 화면, 키보드 조작, 글자 확대, 이미지 크기와 주요 동선을 확인.
- 미리보기 환경에서 기존 단위·회귀·흐름 검증 후 단계적으로 운영 적용. 운영 build의 prebuild가 환경에 따라 DB 작업을 수행하므로 운영 자격 증명으로 로컬 검증을 실행하지 않음.
