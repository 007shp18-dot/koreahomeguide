## 1. 디자인 토큰 — 테스트가 잠금

`v2/apps/web/test/design-tokens.test.ts`가 아래 값을 **정확히** 검사합니다. 한 글자도 바꾸지 마십시오.

```css
--ink:            #201e1d
--canvas:         #f3f2f2
--surface:        #eae9e9
--surface-strong: #ffffff
--muted:          #5d5958
--divider:        #8c8a89
--line:           #d7d3d3
--accent:         #1d4ed8
--accent-soft:    #dbe4ff
--focus-ring:     #1d4ed8
--radius:         0px
--site-width:     1240px
```

- 색 리터럴은 `globals.css` 밖에 하나도 없어야 합니다. `grep -rE "#[0-9a-fA-F]{3,6}" app components --include=*.tsx` 결과 0건.
- 구조 괘선 **2px**, 행 구분 1px `--line`. 반경 0, 그림자 없음.
- 포커스 링은 정확히 `2px`이며 `var(--focus-ring)` 또는 `var(--ink)`만 허용.
- Archivo는 **번들되어 있습니다.** `fonts.googleapis.com`을 참조하면 테스트가 실패합니다.
- 숫자에 `font-variant-numeric: tabular-nums`.

### ⚠ 대비 제약 (신규 UI에서 반드시 지킬 것)

`--muted`(#5d5958)를 `--ink`(#201e1d) 배경 위에 쓰면 대비 **2.40:1** — AA 실패입니다.
`--accent`(#1d4ed8)를 `--ink` 배경 위에 쓰면 **2.48:1** — 역시 실패입니다.

**잉크 배경 블록 위의 본문은 `--canvas`(14.86:1)를 쓰십시오.** 잉크 위 강조가 필요하면 `--accent-soft`를 쓰고, `--accent`는 밝은 배경 위에서만 씁니다. 현재 저장소의 `normalTextPairs`는 `['--muted','--ink']` 조합을 검사하지 않으므로 테스트를 통과해도 안전하지 않습니다.

### 상태는 색이 아니라 획과 채움으로 (v2 §1 그대로)

| 표현 | 뜻 |
|---|---|
| 채움 | 확정된 과거 실적 |
| **빗금** | **표본 부족 · 미완성 · 아직 안 참** |
| **2px 외곽선 + 투명 채움** | **확정된 미래** (예측 아님) |
| 실선 1px | 미탑재 |

빗금 또는 외곽선이 들어간 차트에는 **범례 2항목 이상**을 반드시 렌더합니다. 예외 없음.
빗금을 확정된 미래 데이터에 쓰면 그 화면의 논지가 뒤집힙니다.

## 2. 절대 규칙

### 계산·표시

| # | 규칙 |
|---|---|
| R1 | 표본이 부족한 구간은 **비웁니다.** 상위 지역 평균·0·추정치로 채우지 않습니다 |
| R2 | 전환율은 **계약에 적힌 보증금**에서 읽습니다. 목표 보증금의 요율을 쓰지 않습니다 |
| R3 | 측정 구간 밖은 **연장하지 않고 최근접 앵커값을 유지**합니다. UI에 `측정 구간 밖` 표기 |
| R4 | 요율은 **주택 유형**별로 나눕니다. 지역별로 나누지 않습니다 |
| R5 | 보증금 **원금은 비용이 아닙니다.** 월 부담 합계에 원금을 넣지 않습니다 |
| R6 | 산출 숫자 옆에 출처·기간·방법·경계를 함께 둡니다 (기존 8줄 블록 재사용) |
| R7 | **JSX에 숫자 리터럴을 쓰지 않습니다.** 화면의 모든 숫자는 계산 함수의 반환값입니다 |
| R8 | 내부 계산 단위는 전부 **원(정수)**. 억·만원·평은 표시 시점에만 변환 |
| R9 | 빈 상태는 **제목 / 사유 / 다음 행동** 3요소를 갖습니다. 사유 없는 `—`는 고장으로 읽힙니다 |
| R10 | SVG `<text>`로 축 라벨을 그리지 않습니다. HTML로 렌더합니다 |

### 카피 — 위반 시 즉시 반려

1. **예측 문구 금지.** `오를 / 내릴 / 전망 / 예상 가격 / 유망` 전부 금지. 확정된 사실만 쓰고 해석은 사용자에게 넘깁니다.
2. **우월성 주장 금지.** `가장 정확한 / 최고의 / 유일한` 금지.
3. **감정평가 어휘 금지.** `감정평가 / 감정가 / 평가액`은 부정문(`이것은 감정평가가 아닙니다`) 안에서만 씁니다.
4. **경쟁 서비스·중개사를 이름으로 지목하지 않습니다.**
5. **광고 호가와 신고 계약을 비교하지 않습니다.** 비교는 항상 계약 대 계약입니다.
6. 전환 비교의 프레임은 **"보증금 기준이 달라서 비교가 안 된다"**이지, "광고가 틀렸다"가 아닙니다. **`광고된 숫자는 정확합니다. 기준이 다를 뿐입니다.`** 이 취지의 문장을 유지하십시오.
7. 모르면 모른다고 씁니다: `확인되지 않음`, `비움`, `측정 구간 밖`.
8. **어떤 모델 정확도 수치(MdAPE 등)도 게시하지 마십시오.** `/trust/` 05의 게이트를 유지합니다.

### 출력 형식

- 파일 경로를 명시한 **전체 파일 단위**로 출력합니다. 조각·`...` 생략 금지.

#### 계산 엔진

실측 앵커 (계약 보증금 → 연 전환율). **이 값을 바꾸지 마십시오.**

```ts
// [계약 보증금(억), 연 전환율(%)]
const CONVERSION = {
  apartment: [[0.3,4.95],[0.5,4.81],[1,4.72],[1.5,4.66],[2,4.61],[3,4.55],[4,4.50],[5,4.47]],
  officetel: [[0.3,6.00],[0.5,5.72],[0.75,5.45],[1,5.24],[1.5,5.00],[2,4.80]],
};
// 측정 구간: 아파트 3,000만–5억 / 오피스텔 3,000만–2억
```

조회 규칙: ① 키는 **계약에 적힌 보증금**(R2) ② 앵커 사이는 선형 보간 ③ 구간 밖은 최근접 앵커값 **유지**(R3), UI에 점선 + `측정 구간 밖 — 연장하지 않고 유지`.

```ts
// base: 기준 보증금(원), dep: 계약 보증금(원), rent: 월세(원)
function monthlyBurden(base, dep, rent, assetType) {
  const r = conversionRateAt(dep, assetType) / 100;   // R2
  return rent + Math.max(0, dep - base) * r / 12;     // R5: 원금 미포함
}
const flipped = Math.sign(rentA - rentB) !== Math.sign(burdenA - burdenB);
```

#### 반드시 통과할 테스트 (vitest, 구현 전에 먼저 작성)

- `conversionRateAt(50_000_000, 'apartment')` → `4.81`
- `conversionRateAt(500_000_000, 'apartment')` → `4.47`
- `conversionRateAt(300_000_000, 'officetel')` → `4.80` (측정 구간 밖 유지)
- `conversionRateAt(20_000_000, 'apartment')` → `4.95` (하한 밖 유지)
- `monthlyBurden(base = dep)` → 적힌 월세와 **정확히 동일**
- 보증금 원금이 월 부담에 **절대** 포함되지 않음 (`base=0`에서 dep의 1/12이 아님을 확인)
- `flipped`가 `true`가 되는 조건 쌍을 최소 1개 케이스로 고정
- 입력이 0 / 공백 / 음수이면 결과는 `—`이고 예외를 던지지 않음

- 하단 고정 문구 3개:

### 세션 2 · 구 페이지 정직성 — 데이터 작업 없음

**붙일 것**: §0 §1 §2 + 명세 v2의 F03·F04

이 세션은 **새 데이터가 필요 없습니다.** 이미 화면에 있는 값을 다르게 읽어주는 것뿐입니다.

#### 2-1. 중간 절반 폭을 문장으로 (v2 F03)

지금 `MIDDLE HALF ₩239,250,000–₩350,000,000`이 숫자로만 있습니다. 판정을 붙입니다.

```ts
const spreadRatio = (p75 - p25) / median;
const verdict = spreadRatio < 0.28 ? 'narrow'
              : spreadRatio < 0.55 ? 'moderate' : 'wide';
```

| 판정 | 문구 |
|---|---|
| narrow | 중간 절반이 {폭} 안에 모여 있습니다. 단지 간 편차가 작아 이 숫자를 협상 근거로 쓸 만합니다. |
| moderate | 중간 절반이 {폭}에 걸쳐 있습니다. 단지를 좁히면 더 선명해집니다. |
| wide | 중간 절반이 {폭}에 걸쳐 있습니다. 구 단위 중앙값으로는 판단할 수 없으니 단지를 특정해야 합니다. |

칩: `narrow`는 잉크 외곽선, `wide`는 accent 외곽선.

#### 2-2. RECENT CHANGE에 표본 이동을 붙입니다 — **이 세션의 핵심**

현재 랭킹·구 페이지에 아무 경고 없이 이런 값이 나옵니다:

```
성북구  +23.4%   강동구  +23.1%   금천구  +20.0%   구로구  +18.8%
```

전세 중앙값이 3개월에 23% 오르는 일은 드뭅니다. **표본이 바뀐 것일 가능성이 큽니다.** 지금 화면은 그 가능성을 말하지 않습니다.

**요구**: 변화율 옆에 두 구간의 표본 수를 항상 병기합니다.

```
+23.4%  ·  n 61 → 44
```

그리고 다음 조건 중 하나라도 걸리면 변화율을 **회색으로 낮추고** 아래 주석을 답니다.

```ts
const shaky =
  Math.abs(pct) >= 10 ||                        // 큰 변화
  nPrior < 30 || nLatest < 30 ||                // 얇은 표본
  Math.abs(nLatest - nPrior) / nPrior >= 0.25;  // 표본 자체가 이동
```

> 주석: `이 구간은 표본 수도 함께 움직였습니다. 변화율만으로 시세 변동을 읽지 마십시오.`

#### 2-3. 미완성 구간 (v2 F04)

`filedAt`이 오늘로부터 60일 이내인 월은 `incomplete: true`입니다. 신고 기한 30일 + 반영 지연 때문에 최근 구간은 계속 채워집니다.

- 해당 월 막대는 **빗금**, 축 라벨은 accent
- **범례 2항목 필수**: `확정` / `신고 진행 중`
- 고정 문구: `최근 두 달은 신고 기한(30일)이 지나지 않아 계속 채워집니다. 낮아 보이는 것은 거래 감소가 아닙니다.`
- **미완성 월을 전월·전분기 대비 비교의 기준으로 쓰지 마십시오.** 현재 `2026-01/2026-07` 구간이 완료 구간인지 검증하고, 아니라면 변화율 계산에서 제외하십시오.

#### 2-4. LOCAL QUOTE 축을 공통 컴포넌트로 승격

`min / p25 / median / p75 / max` 축에 사용자 입력 금액을 찍는 컴포넌트가 **구 페이지에만** 있습니다. 이걸 `components/`로 빼서 **랭킹 행, 단지 페이지, Check 결과**에서도 쓰십시오. 새로 만들지 말고 이동시키십시오.

#### 합격 조건

- [ ] 25구 전부에서 변화율 옆에 `n A → B`가 렌더됨
- [ ] `shaky`인 구는 변화율이 회색이고 주석이 붙음
- [ ] 폭 판정 칩이 세 값(narrow/moderate/wide) 모두 실제로 나타나는 구가 존재
- [ ] 미완성 월 막대에 빗금 + 범례 2항목
- [ ] LOCAL QUOTE 축이 최소 3개 페이지에서 같은 컴포넌트로 렌더됨

### 세션 3 · 단지 페이지 확장

**붙일 것**: §0 §1 §2 + 명세 v3의 S7·S8·S9

#### 3-1. 층을 씁니다

MOLIT 전월세 API는 **층 정보를 제공합니다.** 그런데 지금 `03 / RECENT RECORDS` 표가 4열뿐입니다:

```
현재  Filed month | Area | Contract | Jeonse deposit
변경  Filed month | Area | Floor | Contract | Jeonse deposit
```

층을 넣으면 두 가지가 동시에 열립니다. ① 표가 즉시 더 믿을 만해집니다 ② **같은 단지·같은 전용면적·층만 다른 계약 쌍**이 생겨 층 보정 계수의 원재료가 공짜로 확보됩니다.

#### 3-2. 층 보정 계수 (v3 S9 좌측)

같은 단지·같은 면적 밴드 안에서 층 구간별 중앙값을 냅니다. 3열: `구간 / 쌍 수 / 계수`.

- 중층을 `기준`으로 놓고 상대값 표기
- **쌍이 6건 미만인 구간은 `계약 부족`(회색)** — 계수를 내지 않습니다 (R1)
- 하단 산출 근거 1줄: `같은 단지·같은 전용면적 안에서 층만 다른 신고 계약을 비교했습니다. 쌍이 부족하면 비웁니다.`

#### 3-3. 면적 밴드를 축으로

지금 `02 / AREA BANDS`에 `45-55sqm` 한 줄뿐이라 표가 고장난 것처럼 보입니다. 원인은 전 사이트가 45–55㎡ 한 밴드에 갇혀 있기 때문입니다.

**이 세션에서는 화면만 준비합니다** (데이터 확장은 별도 발주). 밴드가 하나뿐일 때는 표 대신 **v2 F02 빈 상태**를 쓰십시오:

> 제목 `다른 면적 구간은 아직 없습니다`
> 사유 `현재 게시 조건은 전용 45–55㎡ 신고 계약으로 고정되어 있습니다.`
> 다음 행동 `다른 면적 구간은 수집 범위가 넓어진 뒤 열립니다.`

⚠ 빈 상태의 면적 표기는 표의 표기와 **문자 단위로 일치**해야 합니다.

#### 3-4. 단지 사실 자료 (v2 F05)

국토부 **공동주택 기본 정보제공 서비스** (data.go.kr `15058453`)를 붙여 준공년도·세대수·난방·주차를 표기합니다.

**출처 구분 문구 필수**: `단지 사실 자료는 계약과 별도 출처입니다. 계약 금액만 국토교통부 신고 데이터이고, 나머지는 공공 건축물대장입니다.`

이 API 연결이 이 세션 범위 밖이면 **행 자체를 만들지 말고** 다음 세션으로 넘기십시오. 빈 껍데기를 만들지 마십시오.

#### 합격 조건

- [ ] 최근 계약 표에 층 열이 있고, 값이 없는 행은 `—`가 아니라 사유가 표기됨
- [ ] 층 계수 패널에서 쌍 6건 미만 구간이 `계약 부족`(회색)으로 렌더됨
- [ ] 면적 밴드가 1개일 때 표가 아니라 3요소 빈 상태가 렌더됨
- [ ] 빈 상태의 면적 표기가 표의 표기와 문자 단위로 일치

### 세션 4 · 커버리지와 갱신 약속 — 작지만 큼

**붙일 것**: §0 §1 §2

#### 4-1. `Not published`를 앞으로 끌어냅니다

지금 지도 범례의 **마지막 줄**에 `Not published · fewer than 5 contracts`가 있습니다. 이걸 자산으로 뒤집습니다.

Explore 상단에 커버리지 패널을 둡니다:

```
이 조건으로 공개 가능한 것
자치구      25 / 25
단지        N / M          ← 실제 계산값
계약        13,026건
공개 못 함  {사유별 건수}
```

무엇을 못 하는지를 먼저 말하는 것이 무엇을 하는지 말하는 것보다 신뢰를 만듭니다. 이 제품의 논지 자체입니다.

#### 4-2. `NEXT UPDATE`

지금 `GENERATED 2026-08-31T23:43:32.884Z`는 있는데 **다음 갱신 약속이 없습니다.** 출처 블록에 한 줄 추가:

```
NEXT UPDATE    {다음 수집 예정일} · 월 1회
```

지키지 못할 주기를 쓰지 마십시오. 확실한 주기만 씁니다. 갱신 주기가 약속이 되면 재방문 이유가 생깁니다.

#### 4-3. 신규·갱신 토글의 기본값

현재 기본이 `All`입니다. 갱신 계약은 예전 조건이 그대로 신고된 것이라 오르는 시장에서 중앙값을 끌어내립니다. 지금 시세를 묻는 사용자가 다수이므로 **기본값을 `New`로 바꾸고**, 세 값을 항상 나란히 보이는 3행 비교를 아래 붙이십시오.

| 행 | 색 |
|---|---|
| 신규 계약 중앙값 | 잉크 |
| 갱신 계약 중앙값 | `--muted` |
| 섞었을 때 + `실제보다 낮게 보입니다` | accent |

3행 비교표는 **어느 탭에서도 항상 세 값을 보여줍니다.** 이게 이 화면의 논증입니다.

#### 합격 조건

- [ ] 커버리지 패널의 모든 숫자가 계산값 (R7)
- [ ] `NEXT UPDATE`가 하드코딩 문자열이 아님
- [ ] 진입 시 기본 탭이 `New`이고 각 탭에 표본 수가 병기됨
- [ ] 3행 비교표가 세 탭 모두에서 동일하게 세 값을 보여줌

### 세션 5 · 한국어

**붙일 것**: §0 §1 §2

서울 국토교통부 신고 계약을 영어로만 게시하고 있습니다. 검색 유입은 한국어이고, `robots`가 `index, follow`로 열린 지금이 결정 시점입니다.

- 구 이름은 이미 한글 부제(`마포구`)가 있으므로 재사용합니다.
