# UI audit — 5 pages, mobile 375px, measured 2026-08-29

Measured on the live site at a 375×812 viewport by reading computed styles and
bounding boxes, not by eye. Every selector and number below came out of the DOM.

Pages: `/`, `/explore/`, `/compare/`, `/community/`, `/tools/seoul-rent-check/`

## Summary

| Page | h-scroll | contrast fails | text < 12px | tap targets < 44px |
|---|---|---|---|---|
| `/` | none | 0 | 19 | 15 |
| `/explore/` | none | 0 | 18 | 12 |
| `/compare/` | none | 0 | 10 | 7 |
| `/community/` | none | 0 | 9 | 6 |
| `/tools/seoul-rent-check/` | none | 0 | 14 | 11 |

## What is already right — do not "fix" these

- **No horizontal overflow on any page at 375px.** `scrollWidth === 375`
  everywhere, zero elements past the viewport. This is the most common mobile
  defect and the site does not have it. Leave the layouts alone.
- **Zero WCAG contrast failures on any page.** Every text node was checked
  against its resolved background at its own size and weight. Do not change any
  text colour; the font-size work below must not be paired with a colour change.

Everything below is type scale and hit area — value changes, not layout changes.

## 4. Compare / Community

| Selector | Now | Target |
|---|---|---|
| `.compare-metrics .is-key > dt` ("DEPOSIT-ADJUSTED ₩/㎡") | 11px | 12px |
| `.compare-market > a` ("Explore this market →") | 26px tall | 44px |
| `.community-hero > a.primary-button` | **26px tall** | 44px |
| `.community-rules > article > span` (step numbers) | 11px | 12px |

`.community-hero .primary-button` is a **primary call to action at 26px tall**.
That is the main action on the page and it is below the tap floor.

11px uppercase tracked eyebrows (`.eyebrow`) are defensible — lowest priority.

## The fix

Scope everything to mobile so the desktop scale is untouched:

```css
@media (max-width: 767px) {
  /* type */
  .rent-size-presets > button { font-size: 13px; }
  .rent-size-presets > button > small { font-size: 12px; }
  .rent-size-unit-toggle { font-size: 13px; }
  .property-type-hint,
  .page-footer > small,
  .page-footer > small a,
  .district-card > span > small,
  .building-section-head > small,
  #explorerMapStatus,
  .compare-metrics .is-key > dt,
  .community-rules > article > span { font-size: 12px; }
  .explorer-map-segments .kg-segmented > button { font-size: 13px; }

  /* standalone controls: grow the box */
  .rent-size-presets > button,
  .rent-size-unit-toggle,
  .khg-consent-actions button,
  .explorer-map-segments .kg-segmented > button { min-height: 44px; padding: 10px 12px; }
  .brand,
  .khg-privacy-settings,
  .compare-market > a,
  .community-hero > a.primary-button,
  .explorer-static-directory-grid > div > a { display: inline-flex; align-items: center; min-height: 44px; }

  /* inline links inside a paragraph: expand the target, do not move the text —
     growing these boxes would break the line rhythm */
  .khg-consent-copy p a,
  .page-footer > small a,
  .footer-contact-action,
  .home-primary-trust > a,
  .explorer-opportunity-links > a { position: relative; }
  .khg-consent-copy p a::after,
  .page-footer > small a::after,
  .footer-contact-action::after,
  .home-primary-trust > a::after,
  .explorer-opportunity-links > a::after {
    content: ""; position: absolute; left: 0; right: 0;
    top: 50%; transform: translateY(-50%); height: 44px;
  }
}
```

## 5. Desktop — the consent banner covers the primary CTA

On `/` at desktop width the banner floats over the area directly below the
Check button, the spot the eye lands after filling the form. It is the first
conversion step on the page and it sits behind an overlay. Dock it to the
bottom edge, or cap its width and pin it to one side. A position change, not a
redesign.

## Verification

Re-run the same measurement on all five pages after the change:

1. 375×812, reload each page.
2. `document.documentElement.scrollWidth === 375` — no new overflow. The padding
   bumps are the risk; this is the check that catches them.
3. No text node with its own text below 12px (eyebrows excepted).
4. Every `a`/`button` with a hit box ≥ 44px, counting the `::after` expansion.
5. Contrast still 0 failures.
