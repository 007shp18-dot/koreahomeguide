# SignedPrice 사업·제품·홍보 재점검 — 2026-09-05

## 판단과 범위

SignedPrice의 초기 사업 중심은 서울·싱가포르의 실제 거래와 주거 제도를 이해하고 계약 조건을 비교하도록 돕는 데이터 서비스다. 첫 검증 고객은 서울에서 집을 구하는 영어·중국어 사용자로 제안한다. 싱가포르는 현재 지원 기능을 안정화하며 두 번째 시장으로 운영한다. 이는 시장 규모나 전환율이 입증된 결론이 아니라, 기존 데이터·도구·언어 투자에 근거한 고객 가설이다.

기존 승인 사항인 색상 유지, Markets / Prices / News / Guides, 세 도시 홈 구조, 서울·싱가포르 제작, 두바이 확장 보류, 자동 기사 발행 금지를 이어간다. 이번 문서는 기존 설계서를 대체하지 않고 우선순위와 성공 기준을 구체화한다. AdSense 활성화는 이번 배포에 포함하지 않는다.

2026년 9월 4–5일 공개 홈·News·서울 Check·싱가포르 Overview를 브라우저로 확인했다. 홈과 Rightmove는 데스크톱 스크린샷도 비교했다. 글로벌 레퍼런스는 공식 공개 페이지의 정보 구조와 기능을 확인했다. 모든 레퍼런스의 모바일/로그인 흐름을 검증한 것은 아니다. 트래픽·Search Console·실매출 자료는 이번 검토에 없으므로 성과나 수요를 추정 수치로 제시하지 않는다.

## 제품 개편 우선순위

홈은 한 문장 가치 제안, 도시 선택, 주요 행동부터 보여준다. 문구 초안은 “Understand local prices before you sign.”이며, 하위 설명은 실제 지원하는 도시·거래 유형을 구체적으로 말한다. 두바이는 기존 세 도시 구조 안에서 준비 상태만 간결하게 알린다. 대표 리포트 카드는 해당 기사로 직접 연결한다.

Prices는 검색의 입구, Markets는 도시별 개요, News는 변화를 이해하는 곳, Guides는 실행 방법을 찾는 곳으로 역할을 고정한다. 글로벌 메뉴는 모든 페이지에서 유지한다. 언어 변경은 가능한 동일 문서/동일 작업으로 이동하고, 대응 문서가 없으면 명확히 안내한다.

| 화면 | 우선 구현/검수 | 완료 기준 |
| --- | --- | --- |
| Overview | 16:9 사진·6:6 그리드, 핵심 지표·기간·Explore 진입 | 지원 기능을 한 화면에서 이해하고 다음 행동 가능 |

| Detail | 신원·검증 사진·거래 분포·비교 근거·출처·Check | 현재 건물/면적 조건을 유지한 가격 비교 |

| 공통 | 최소 12px, 상호작용 44px, 키보드 초점, 오류/빈 상태 | 1440·1024·390px 주요 동선 통과 |

개편의 원칙은 출처를 숨기는 것이 아니라 읽기 순서를 조정하는 것이다. 핵심 답과 다음 행동을 먼저 제공하고, 데이터 옆에 기간·표본·출처를 항상 표시하며 자세한 방법론은 펼쳐볼 수 있게 한다.

## 콘텐츠·정책·인포그래픽 운영

News는 Latest / Policy / Market / Data Stories를 유지한다. Latest는 편집된 자체 콘텐츠의 최신순이다. Policy는 발표일·시행일·변경일·종료일을 분리한다. 동일 정책은 고유 페이지에서 상태와 변경 이력을 관리하고 관련 Guide에도 검토 필요 상태를 전달한다.

정책 글은 “무엇이 바뀌었나 → 누구에게 적용되나 → 언제부터인가 → 계약 전에 무엇을 확인하나 → 공식 원문” 순서로 작성한다. 국적·거주 자격·자산 유형 등 적용 조건을 확인하고, 발표만 된 내용을 시행 중이라고 쓰지 않는다. 추적·초안 작성은 자동화할 수 있지만 출판은 검수 후 진행한다.

| 인포그래픽 유형 | 다루는 질문 | 확인할 데이터 조건 |
| --- | --- | --- |
| 추이 | 가격·거래량이 어떻게 바뀌었나 | 같은 정의·기간 간격·수정 내역 |
| 지역 비교 | 같은 조건에서 어디가 다른가 | 자산 유형·면적·기간·표본 통일 |
| 비용 구성 | 보증금과 월 비용은 어떻게 구성되나 | 관측값과 예시 입력값 분리 |
| 분포 | 내 제안 가격이 비교 사례의 어디에 있나 | 실제 비교 표본·범위·제외 조건 |
| 정책 일정 | 발표와 시행 사이에 무엇을 해야 하나 | 공식 원문과 검토일·적용 대상 |

차트 하나에는 질문 하나를 담는다. DB의 공개 release에서 생성하고 지표 정의·단위·기간·표본·원문 링크·검토일을 함께 내보낸다. 웹용 차트, 접근 가능한 표, 권리가 허용되는 다운로드, 공유용 이미지는 같은 데이터를 사용한다. 정확한 수치 차트를 이미지 생성 모델로 만들지 않는다.

기존 29개 콘텐츠 묶음은 발행 목표가 아니라 검수 재고로 관리한다. 우선 대표 가이드 6–8개와 반복 발행할 데이터 시리즈 2개를 완성한다. 제안 시리즈는 서울 월별 임대 조건 리포트와 싱가포르 자산 유형별 거래 리포트다. 비교 가능한 월별 데이터가 확보되지 않으면 추이 대신 현재 공개 표본의 분포를 제공한다. 정책은 정해진 분량보다 실제 변화 발생을 기준으로 갱신한다.

AdSense는 검수 완료 후 가능한 초기 수익 실험이다. 앞선 대화의 영문 30–40개·중문 10–15개는 내부 제작 목표로만 취급한다. Google의 공개 [참여 요건](https://support.google.com/adsense/answer/9724?hl=en)은 그 수량을 승인 기준으로 제시하지 않는다. 승인이나 수익을 글 개수로 보장하지 않는다.

광고는 핵심 검색·Check 입력·가격 결과를 방해하지 않는 읽기 영역부터 검토한다. 이후 전문 리포트·교육형 브리핑·명확히 구분된 협찬을 실험할 수 있다. 중개 제휴는 별도 단계이며 현재 범위에 포함하지 않는다. 실제 트래픽과 수익 자료가 없으므로 매출 예측을 제시하지 않는다.

## 홍보 방향과 실험

홍보는 질문에 대한 답을 전달하고 그 답을 검증할 사이트 화면으로 연결한다. “사이트 오픈” 소개보다 실제 데이터·정책 해설·조건 비교 예시를 중심으로 한다. 아래 채널은 검증할 후보이며 효과가 입증된 채널이라는 의미는 아니다.

| 1 | 영어 검색 | 전세·월세·관리비·지역별 조건 가이드 | 해당 Guide와 조건이 맞는 Explore/Check | 검색 질문 적합성, 콘텐츠→도구 사용 |
| 2 | 중국어 검색/샤오홍슈 소규모 실험 | 중국어 독자의 질문에 맞춘 원본 설명·차트 | 독립 검수한 중국어 페이지 | 의미 있는 유입, 조건 확인 완료 |
| 3 | LinkedIn·관련 커뮤니티 | 한 질문·한 차트·짧은 해석 | 해당 Data Story | 저장/공유와 후속 사이트 사용 |
| 4 | 대학 국제처·이주 지원 기관 등 제휴 후보 | 반복 질문을 해결하는 안내 자료 | 목적별 가이드 묶음 | 실제 활용 피드백·반복 유입 |
| 5 | 구독 동의 기반 이메일 | 월간 데이터와 중요한 정책 변화 | 최신 리포트/정책 고유 페이지 | 후속 방문·도구 사용·구독 해지 |

초기에는 검색과 보조 채널 하나부터 실험한다. 외부 게시물·메일·기관 연락은 이 문서에서 실행하지 않았다. 광범위한 유료 광고는 착지 페이지의 과제 수행과 측정이 안정된 뒤 검토한다.

Google은 [사람에게 유용한 원본 콘텐츠](https://developers.google.com/search/docs/fundamentals/creating-helpful-content)를 강조하며, [AI 검색 기능에도 기본 SEO 원칙](https://developers.google.com/search/docs/appearance/ai-features)이 적용된다고 설명한다. 따라서 검색용 페이지 양산보다 고유 데이터, 읽을 수 있는 표·텍스트, 일치하는 구조화 데이터, 정확한 내부 링크를 우선한다.

## 유지보수 운영과 측정

데이터 운영은 수집 → 검증 → 공개 projection → 마지막 유효 snapshot → 사용자 화면으로 관리한다. 새 데이터가 실패하면 마지막 검증 자료와 실제 기준일을 유지한다. 사진의 승인 상태·권리·깨진 URL, 좌표의 정밀도, 정책의 검토 기한을 함께 관리한다.

| 주기 제안 | 운영 작업 | 확인 자료 |
| --- | --- | --- |
| 매 배포 | 핵심 여정·언어·계산·레이아웃·회귀 확인 | CI와 배포 환경 결과 |
| 매 수집 | 건수·기간·중복·이상치·공개 권리 확인 | release별 검증 기록 |
| 주간 | 오류·데이터 신선도·검색 막힘·링크·사진 점검 | 오류율·오류 사례·수정 목록 |
| 정책 변화 시 | 공식 원문 검토·상태 수정·관련 글 재검토 | 정책 고유 페이지와 변경 이력 |
| 월간 | 대표 리포트 갱신·유입/사용/비용 검토 | 콘텐츠별 유효 사용과 운영 비용 |

첫 측정 목표는 방문자가 콘텐츠에서 관련 거래를 확인하고 비교까지 진행하는지다. 검색 유입, 콘텐츠→Explore/Check, 비교 완료, 재방문을 단계별로 본다. 현재 분석 이벤트는 콘텐츠 중심이므로 도구의 완료 측정은 별도 설계가 필요하다. 입력 주소·계약 금액을 수집하지 않고 작업 완료 여부만 측정한다. SPA 이동 후 읽기 완료와 차트 표 열기/닫기 이벤트의 정확성을 먼저 확인한다.

보편적 전환율 목표를 가정하지 않는다. 초기 2주 기준선을 수집한 뒤 문구·진입 위치·내부 링크 실험을 비교한다. 검색량이 적으면 비율만으로 결론 내리지 않고 사용자 과제 관찰과 함께 판단한다.

## 바로 이어갈 작업

1. 브라우저 CI 113건 실패를 실제 결함·승인 설계와 다른 기대값·이미지 기준 누락으로 분류한다. 확인된 32px Singapore 링크를 44px 기준으로 수정한다. 테스트를 삭제하거나 기준 이미지를 무검수 승인해 통과시키지 않는다.
2. Preview DB 연결·마이그레이션·공개 projection과 인덱스·비운영 환경 fallback을 검증한다. Neon 요청 신호 수명 수정만으로 운영 timeout 전체 해결을 선언하지 않는다.
3. 공개 사이트에서 확인한 내부 ID 입력·잘못된 초기 문구·헤더·언어 전환 문제가 개편본에서 해소되는지 대조한다.
4. News의 외부 피드 공개 제거, 정책 원문 유형, 인포그래픽 숫자/기간/표본을 검수한다.
5. 승인된 개편을 배포한 뒤 대표 사용자 과제와 핵심 콘텐츠를 확인하고, 검색+보조 채널 하나의 홍보 실험을 시작한다.
